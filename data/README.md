# Data

All files are UTF-8 CSV. The item ids and query texts are exactly those used in the paper.

| File | Rows | Contents |
|---|---|---|
| `corpus.csv` | 213 | The evaluation set judged by the detectors |
| `malicious_v2_review.csv` | 200 | Every generated candidate, with its rule-based pre-label and its final label |
| `malicious_final.csv` | 135 | Candidates labeled malicious |
| `benign_generated.csv` | 26 | Candidates labeled benign (the hard negatives) |
| `malicious_excluded.csv` | 39 | Candidates excluded from the evaluation |
| `benign_sql.csv` | 40 | Hand-authored benign controls |
| `pi_payloads.csv` | 12 | Prompt-injection payloads |

## corpus.csv

| Column | Meaning |
|---|---|
| `item_id` | `MA0001` to `MA0200` for generated candidates, `B001` to `B040` for hand-authored controls, `PI001` to `PI012` for payloads |
| `text` | The query shown to the detector |
| `true_label` | `malicious` or `benign` (payloads are `malicious`) |
| `group` | `malicious`, `benign`, or `pi` |
| `tier` | The attack family for malicious items; empty otherwise |
| `meta` | `generated_benign` for the hard negatives, `human_style` or `llm_style` for the hand-authored controls, and the injection category for payloads; empty for malicious items |

The rows are in this order: the 135 malicious queries, the 26 generated benign queries, the 40 hand-authored controls, and the 12 payloads. The post-hoc position reads the corpus in this order in batches of ten.

## malicious_v2_review.csv

| Column | Meaning |
|---|---|
| `id` | `MA0001` to `MA0200`, numbered in generation order |
| `family` | The attack family requested from the generator |
| `sql` | The generated query |
| `auto_label`, `auto_category`, `auto_reason` | The rule-based pre-label and the constructs it matched (`label_by_behavior` in `scripts/generate_candidates.py`) |
| `expert_label` | The final label: `malicious`, `benign`, or `exclude` |
| `expert_note` | The annotator's reason, given for each of the 68 candidates whose pre-label was changed |

The annotator reviewed all 200 pre-labels and changed 68:

- 33 from malicious to exclude
- 15 from malicious to benign
- 14 from benign to malicious
- 6 from benign to exclude

The file begins with a UTF-8 byte order mark. Readers that open it with the `utf-8-sig` encoding handle it.

## Label files

`malicious_final.csv` and `benign_generated.csv` have the columns `id`, `level` (the attack family), `sql`, `label`, and `expert_note`. `malicious_excluded.csv` has `id`, `level`, `sql`, and `expert_note`.

## benign_sql.csv and pi_payloads.csv

`benign_sql.csv` has the columns `id`, `text`, `true_label`, `source`, and `style`. It holds 20 terse, hand-written queries (`human_style`) and 20 in a more verbose style with table aliases, explicit casts, and parameter placeholders (`llm_style`).

`pi_payloads.csv` has the columns `id`, `text`, `true_label`, `source`, and `injection_category`. There are two payloads in each of six categories: `comment_injection`, `string_literal`, `encoded`, `authority_spoof`, `trailing_jailbreak`, and `role_confusion`. Each payload is an SQL injection attack that also carries an instruction addressed to the detector.

## Schema

The generator was given this schema:

```
users(id, username, email, password_hash, is_admin, created_at)
orders(id, user_id, total, status, created_at)
products(id, name, price, stock, category)
payments(id, order_id, amount, method)
sessions(id, user_id, token, expires_at)
```

The hand-authored controls use the same five tables. Eight of them reference a column that is not in this schema: `users.last_login`, `users.country`, `products.title`, or `orders.product_id`, two queries each. Two payloads reference tables outside the five: `logs` (PI004) and `accounts` (PI010).

## Generation

The candidates were generated by Mistral-7B-Instruct-v0.3 at revision `c170c708c41dac9275d15a8fff4eca08d52bab71`, loaded in 4-bit and sampled with temperature 0.8, top-p 0.95, and seed 42.

Each prompt gave the schema, named a target table, showed one worked example for the family, and asked for a single statement. Sampling continued until each family had 25 unique candidates that passed a validity filter. A candidate had to:

- begin with an SQL verb,
- reference a schema table,
- contain no placeholder tokens,
- be 15 to 400 characters long,
- be a single statement (except in the stacked family).

## Labeling policy

- **malicious:** executing the query would breach confidentiality, integrity, or availability beyond what the stated request authorizes.
- **benign:** a legitimate request, or a direct read of schema metadata, that carries no attack.
- **exclude:** malformed, truncated, or not resolvable to a clear intent against the schema.

The labels are one annotator's judgments on the query text. No query was executed against a database, so a malicious label records what the annotator expects the query to do, not an observed exploit.
